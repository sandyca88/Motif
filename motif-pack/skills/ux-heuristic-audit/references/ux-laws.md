# UX Laws & Heuristics Cheat Sheet (for citing in findings)

| Principle | One-line meaning | Typical finding |
|-----------|------------------|-----------------|
| Nielsen #1 Visibility of system status | Always show what's happening | No loading/progress feedback |
| Nielsen #2 Match with real world | Use users' words, natural order | Internal jargon in labels |
| Nielsen #3 User control & freedom | Easy undo/exit | No undo for delete; modal can't be closed |
| Nielsen #4 Consistency & standards | Same thing looks/acts the same | 3 button styles for primary action |
| Nielsen #5 Error prevention | Stop errors before they happen | No confirmation for destructive action |
| Nielsen #6 Recognition over recall | Show options, don't make people remember | Codes/IDs users must memorize |
| Nielsen #7 Flexibility & efficiency | Shortcuts for experts | No keyboard shortcuts / bulk actions |
| Nielsen #8 Aesthetic & minimalist | Remove what doesn't help | Competing visuals around CTA |
| Nielsen #9 Help recover from errors | Plain-language errors with a fix | "Error 400" |
| Nielsen #10 Help & documentation | Contextual help when needed | No hint for complex field |
| Fitts's law | Big + close targets are faster | Tiny primary button far from focus |
| Hick's law | More choices, slower decisions | 9 equal CTAs in hero |
| Jakob's law | Users expect patterns from other sites | Logo not linking home, unusual nav |
| Miller's law (7±2) | Chunk information | 15-item unchunked menu |
| Proximity (Gestalt) | Close = related | Label closer to wrong input |
| Similarity (Gestalt) | Alike = same function | Links styled like body text |
| Von Restorff effect | The different item stands out | Primary CTA same style as others |
| Serial position effect | First & last items remembered | Key nav item buried in middle |
| Peak-end rule | Experiences judged by peak + end | Flat, forgettable success state |
| Doherty threshold | < 400ms response feels instant | No optimistic UI on slow actions |
| Tesler's law | Complexity must live somewhere: absorb it for users | User asked to format data manually |
| Goal-gradient effect | Motivation rises near completion | No progress indicator in multi-step form |
| Zeigarnik effect | Unfinished tasks are remembered | No checklist/"continue setup" prompt |
| Aesthetic-usability effect | Pretty is perceived as easier | Polished but broken: don't let it hide issues |
